# 집에서 이어서 하기

> 워크샵을 마치며 — 돌아가서 이 문서부터 다시 여세요

## 워크샵에서 가져가는 것

| | 어디에 있나 |
|---|---|
| 웹 화면 | `https://<내아이디>.github.io/<저장소이름>/` — 워크샵 이후에도 계속 살아 있습니다 |
| 코드 전부 | `https://github.com/<내아이디>/<저장소이름>` |
| 데이터 | 내 Google Drive의 스프레드시트 |
| 문서 | 내 저장소의 `docs/` 폴더 (워크샵에서 본 이 문서들이 그대로 복사돼 있습니다) |

---

## 집 PC 세팅 4단계

1. **Git 설치** — [git-scm.com](https://git-scm.com/download/win) → 다운로드 → 계속 `다음`만 눌러도 됩니다
2. **Claude Desktop 설치** — [claude.ai/download](https://claude.ai/download)
3. **로그인** — Claude Desktop에 로그인하고 `Code` 탭이 열리는지 확인
4. **내 작업 내려받기** — 빈 폴더를 하나 만들고 Claude Code에서 그 폴더를 연 다음:

```
아래 GitHub 저장소를 지금 폴더로 가져와줘.
https://github.com/<내아이디>/<저장소이름>

가져온 다음 docs/ 폴더의 문서들을 읽고,
이 프로젝트가 지금 어디까지 만들어져 있는지 정리해서 알려줘.
```

> 처음 `push`할 때 GitHub 로그인 창이 한 번 뜹니다. 브라우저에서 승인하면 됩니다.

---

## 막혔을 때 순서

1. **같은 프롬프트를 한 번 더** 실행
2. `docs/`에서 해당 문서를 다시 읽기 ([시트 연결](connect-sheets.md) 오류 표부터 보세요)
3. [디버깅 문서](debugging.md)의 **상황 설명 4줄**로 Claude Code에게 질문
4. 그래도 안 되면 **질문 채널**에 올리기 — 이때도 **상황 설명 4줄**로 적어 주세요

> 질문 채널에 "안 돼요"라고만 올리면 되묻느라 하루가 갑니다.
> 4줄을 채워 올리면 대개 한 번에 답이 갑니다. 워크샵에서 배운 것 중 실전에서 가장 쓸모 있는 습관입니다.

## 배운 것 (한 장 요약)

- **정규화** — 표를 쪼개서 같은 값이 반복되지 않게 만드는 것. 원래는 RDB라는 전문 프로그램이 하는 일입니다.
- **바이브코딩** — 코드를 직접 쓰는 대신 무엇을 원하는지 말로 설명해서 만드는 방식.
- **배포** — 내 PC의 파일을 인터넷 주소에서 볼 수 있게 올리는 것.
- **삭제의 무게** — 삭제만은 되돌릴 수 없어서 앱에 넣지 않았습니다. 엔지니어들이 삭제를 다루는 방식은 [삭제 이야기 문서](about-delete.md)에.
- **상황 설명 4줄** — 하려던 것 / 한 동작 / 일어난 일 / 기대한 것.
- **같은 Claude, 다른 책상** — Cowork도, Code도, Chat도 전부 같은 Claude입니다. 화면이 다를 뿐 능력은 하나예요.
