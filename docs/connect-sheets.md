# STEP 06 · 내 화면을 Google Sheets에 연결하기 ⭐

> STEP 05까지 마친 다음에 — 이 워크샵의 본론입니다

---

## 먼저 · 연결은 두 갈래입니다

헷갈리기 쉬운 부분이라 먼저 정리합니다. **길이 두 개고, 하는 일이 다릅니다.**

| | ① Claude Code가 읽기 | ② 내 웹페이지가 읽고 쓰기 |
|---|---|---|
| 언제 | STEP 04에서 이미 해 봤습니다 | 지금 이 단계 |
| 누가 | 내 PC의 Claude Code | 인터넷에 배포된 내 웹페이지 |
| 무엇을 | 내 시트의 **열 구조 파악** | 데이터 **생성·조회·수정** |
| 방법 | **Google Drive 커넥터** (STEP 02에서 연결해 둔 것) | Google 로그인(OAuth) |
| 로그인 | 커넥터에 이미 돼 있음 | 버튼 누를 때마다 |

①은 Claude Code에게 "내 데이터가 이렇게 생겼어"를 알려주기 위한 것이었고,
지금 만드는 ②가 실제 여러분 앱의 기능입니다. **①이 된다고 ②가 되는 게 아닙니다** —
여러분의 웹페이지는 Claude가 아니라서, 자기만의 열쇠(클라이언트 ID)로 따로 로그인해야 합니다.

---

## 🚨 가장 중요한 규칙 하나

**시트 연결(②)은 배포된 주소에서만 동작합니다.**

내 PC의 파일을 브라우저로 직접 여는 방식(주소가 `file:///C:/...`로 시작)에서는
Google이 보안상 로그인을 거부합니다. 반드시 이렇게 하세요:

> 코드 수정 → **"배포해줘"** → `https://<내아이디>.github.io/<저장소이름>/` 에서 확인

기능 하나 만들 때마다 배포하세요. 1~2분이면 됩니다.
"화면은 되는데 시트가 안 돼요"의 90%가 이 규칙을 안 지켜서 생깁니다.

---

# Part 1 · Google 로그인 준비

## 내 클라이언트 ID 확인

[STEP 05 문서](google-cloud-setup.md)에서 만든 **클라이언트 ID**가
`config.js`에 들어 있어야 합니다. 아직 안 만들었다면 지금 그 문서를 따라 만들고 돌아오세요.

직접 만드는 이유: 이 앱을 온전히 여러분 소유로 만들고,
나중에 회사 팀원들과 공유할 때 여러분이 직접 관리할 수 있게 하기 위해서입니다.

> **클라이언트 ID는 비밀번호가 아닙니다.** 웹페이지 코드에 그대로 들어가는 공개된 값이라
> GitHub에 올라가도 괜찮습니다. 여러분의 시트에는 여러분이 로그인해야만 접근됩니다.

## "확인되지 않은 앱" 경고 화면

로그인할 때 이런 화면이 나옵니다:

> **Google에서 확인하지 않은 앱**
> 이 앱은 Google에서 확인하지 않았습니다.

**정상입니다.** 우리가 직접 만든 개인용 앱이라 Google 심사를 받지 않아서 그렇습니다.

1. **`고급`** 클릭
2. 아래쪽 **`<앱이름>(안전하지 않음)으로 이동`** 클릭
3. 체크박스 **`모두 선택`** 에 체크
4. **`계속`**

3번의 체크박스를 빠뜨리면 로그인은 되는데 시트를 못 읽습니다. **꼭 체크하세요.**

# Part 2 · 기능 만들기 (라운드 A → B → C)

한 번에 하나씩 합니다. **앞 단계가 끝나야 다음으로 갑니다.**

## 라운드 A · 조회 (화면에 데이터 띄우기)

```
CLAUDE.md의 "시트 연동 구현 규칙"을 먼저 읽고, 그 규칙을 그대로 지켜서 만들어줘.

지금 만들 것은 조회 기능이야.
1. 화면 위에 "Google 계정으로 연결" 버튼을 하나 만들어줘.
2. 그 버튼을 누르면 Google 로그인이 뜨고, 로그인하면
   내 시트의 데이터를 표로 화면에 보여줘.
3. 다 만들면 어떤 파일을 왜 바꿨는지 두 문장으로 설명하고, 배포해줘.
```

배포 후 **내 URL을 새로고침**하고 버튼을 눌러 확인합니다.
확인이 끝나면 **시트에서 값을 하나 직접 고치고** 페이지를 새로고침해 보세요. 화면이 따라옵니다.

### ✅ 체크포인트 A
- [ ] 배포된 내 주소에서 Google 로그인이 된다
- [ ] 내 시트 데이터가 표로 보인다

## 라운드 B · 생성 (화면에서 넣은 값이 시트에 쌓이기)

```
이제 데이터 추가 기능을 만들어줘.

1. 시트의 열 이름들에 맞춰서 입력 폼을 만들어줘.
2. "추가" 버튼을 누르면 시트 맨 아래에 새 행으로 들어가게 해줘.
3. 추가되면 화면의 표도 바로 갱신되게 해줘.
4. 다 되면 배포해줘.
```

**시트 탭을 열어 두고** 화면에서 추가해 보세요. 시트에 행이 실제로 늘어나는 걸 눈으로 확인합니다.

### ✅ 체크포인트 B
- [ ] 화면에서 입력한 값이 시트에 새 행으로 들어간다

## 라운드 C · 수정 (화면에서 고친 값이 시트에 반영되기)

```
이제 수정 기능을 만들어줘.

1. 표의 각 행에 "수정" 버튼을 달아줘.
2. 누르면 그 행의 값을 고칠 수 있게 하고, 저장하면 시트의 그 행이 바뀌게 해줘.
3. 다 되면 배포해줘.
```

### ✅ 체크포인트 C
- [ ] 화면에서 고친 값이 시트의 해당 행에 반영된다

먼저 끝났다면 [더 좋게 만들기](ideas.md)에서 골라 이어 가세요.

## ❌ 삭제는 만들지 않습니다

눈치채셨겠지만 이 워크샵에 삭제 기능은 없습니다. 빠뜨린 게 아니라 **일부러 뺐습니다.**
생성·수정은 실수해도 되돌릴 수 있지만 **삭제만은 되돌릴 수 없기 때문**입니다.

왜 그런지, 현업 엔지니어들은 삭제를 어떻게 다루는지는 [삭제 이야기 문서](about-delete.md)에서
따로 다룹니다 — 마무리 강의 때 함께 읽습니다.

당장 지워야 할 행이 있으면 **Google Sheets에서 직접** 지우세요.
실수해도 시트의 **파일 → 버전 기록**으로 되돌릴 수 있습니다.

Claude Code에게 삭제 기능을 요청해도 만들어 주지 않습니다. (`CLAUDE.md`에 그렇게 적혀 있습니다)

# 자주 나오는 오류

| 화면에 나오는 말 | 뜻과 해결 |
|---|---|
| `origin_mismatch` / `redirect_uri_mismatch` | 지금 열고 있는 주소가 등록되지 않았습니다. **`file:///`나 로컬에서 열지 않았는지** 확인하세요. 배포된 `https://...github.io/...` 주소에서 열어야 합니다. |
| `idpiframe_initialization_failed` | 브라우저가 쿠키를 막고 있습니다. 시크릿 모드가 아닌 일반 창에서, 서드파티 쿠키 차단을 풀고 시도하세요. |
| `403 · The caller does not have permission` | 로그인은 됐는데 권한이 없습니다. 로그인 때 **체크박스 `모두 선택`** 을 빠뜨렸을 가능성이 큽니다. 브라우저에서 Google 로그아웃 후 다시 연결하세요. |
| `Unable to parse range` | `SHEET_NAME`이 실제 탭 이름과 다릅니다. 시트 아래쪽 탭 이름을 **글자 하나까지 똑같이** 맞추세요. |
| `Requested entity was not found` | `SPREADSHEET_ID`가 틀렸습니다. 주소창의 `/d/` 와 `/edit` 사이만 복사했는지 확인하세요. |
| 아까는 됐는데 지금 아무 반응이 없음 | Google 로그인은 **1시간쯤 지나면 만료**됩니다. "Google 계정으로 연결" 버튼을 다시 누르세요. (쉬었다 돌아온 뒤에 자주 발생합니다) |

어느 것에도 해당하지 않으면 [debugging.md](debugging.md)의 **상황 설명 4줄**로 Claude Code에게 말하세요.
