# STEP 05 · 내 Google Cloud 설정 — 클라이언트 ID 만들기

> STEP 05 · 시트 연결(STEP 06)을 시작하기 전에 합니다 · 약 15~20분

## 왜 이걸 각자 만드나요

여러분의 앱이 여러분의 시트에 접근하려면, Google에 **"이 앱은 이런 앱입니다"** 하고
등록해 둬야 합니다. 그 등록증이 **클라이언트 ID**입니다.

이 등록을 **여러분 계정으로 직접** 합니다. 그래야:

- 이 앱이 **온전히 여러분 소유**가 됩니다 — 워크샵이 끝나도, 누구 허락 없이도 계속 동작합니다
- 나중에 **회사 팀원들에게 앱을 공유**할 때, 여러분이 직접 팀원을 추가할 수 있습니다
- 앱 이름·설정을 여러분 서비스에 맞게 바꿀 수 있습니다

화면이 낯설고 영어가 섞여 있지만, 하는 일은 **회원가입 양식 채우기** 수준입니다.
아래를 순서대로 따라오세요. 막히면 손을 드세요.

## 시작 전 확인

- **개인 Google 계정**으로 진행하세요. 회사 계정(Workspace)은 관리자 정책 때문에
  프로젝트 생성이 막혀 있을 수 있습니다. 시트를 올린 그 계정이면 됩니다.
- **신용카드·결제 등록은 필요 없습니다.** 여기서 쓰는 기능은 전부 무료 범위입니다.
  결제를 요구하는 화면이 나온다면 잘못 들어간 것이니 손을 드세요.

---

## 1단계 · 프로젝트 만들기

1. 브라우저에서 [console.cloud.google.com](https://console.cloud.google.com) 접속
2. 처음이라면 약관 동의 화면이 나옵니다 → 국가 선택, 동의 체크 → **`동의 및 계속`**
3. 화면 **왼쪽 위**의 프로젝트 선택 버튼(`프로젝트 선택` 또는 기존 프로젝트 이름) 클릭
4. 뜨는 창의 오른쪽 위 **`새 프로젝트`** 클릭
5. 프로젝트 이름: 내 서비스 이름을 영어로 (예: `my-inventory-app`) → **`만들기`**
6. 잠시 후 오른쪽 위 알림(🔔)에 "프로젝트 만들기 완료"가 뜹니다 →
   알림에서 **`프로젝트 선택`** 을 눌러 방금 만든 프로젝트로 이동합니다

> 💡 이후 모든 단계는 **방금 만든 프로젝트 안에서** 합니다.
> 화면 왼쪽 위에 내 프로젝트 이름이 보이는지 수시로 확인하세요.

## 2단계 · Google Sheets API 켜기

내 프로젝트가 "시트를 다루겠다"고 선언하는 단계입니다.

1. 왼쪽 위 **☰ 메뉴** → **`API 및 서비스`** → **`라이브러리`**
2. 검색창에 `Google Sheets API` 입력 → 검색 결과 클릭
3. 파란색 **`사용 설정`** (Enable) 버튼 클릭
4. "API 사용 설정됨" 화면이 나오면 완료

## 3단계 · OAuth 동의 화면 만들기

사용자가 Google 로그인할 때 보게 될 **동의 화면**을 설정합니다.
(처음 사용자는 여러분 자신, 나중엔 여러분의 팀원입니다)

1. **☰ 메뉴** → **`API 및 서비스`** → **`OAuth 동의 화면`**
2. 처음이라면 **`시작하기`** 를 누르고 다음을 채웁니다:
   - **앱 이름**: 내 서비스 이름 (예: `우리 공장 입고 관리`) — 로그인 화면에 이 이름이 뜹니다
   - **사용자 지원 이메일**: 내 이메일 선택
   - **대상(Audience)**: **`외부(External)`** 선택
   - **연락처 정보**: 내 이메일 입력
   - 약관 동의 → **`만들기`**
3. 만들기가 끝나면 왼쪽 메뉴에서 **`대상(Audience)`** 을 클릭합니다
4. 아래쪽 **`테스트 사용자(Test users)`** 에서 **`+ Add users`** 클릭 →
   **내 Google 이메일**을 입력하고 저장

> 💡 **나중에 팀원에게 앱을 공유할 때**도 바로 이 자리입니다.
> 팀원의 Google 이메일을 테스트 사용자에 추가하면 그 사람도 로그인할 수 있습니다. (최대 100명)

> ⚠️ 게시 상태는 **`테스트`** 그대로 둡니다. "앱 게시" 버튼은 누르지 마세요 —
> 게시하면 Google의 정식 심사(수 주 소요)가 시작됩니다. 우리 용도로는 테스트 모드가 맞습니다.

## 4단계 · 클라이언트 ID 만들기

드디어 등록증을 발급받습니다.

1. **☰ 메뉴** → **`API 및 서비스`** → **`사용자 인증 정보(Credentials)`**
2. 위쪽 **`+ 사용자 인증 정보 만들기`** → **`OAuth 클라이언트 ID`**
3. **애플리케이션 유형**: **`웹 애플리케이션`**
4. **이름**: 아무거나 (예: `web`) — 내부 관리용이라 사용자에게 안 보입니다
5. **승인된 자바스크립트 원본** → **`+ URI 추가`** → 다음을 입력:
   ```
   https://<내GitHub아이디>.github.io
   ```
   - **주소 끝에 `/` 나 저장소 이름을 붙이지 마세요.** 딱 여기까지만 씁니다.
   - 여기 등록한 주소에서만 Google 로그인이 허용됩니다. 이게 여러분 앱의 보안 장치입니다.
6. **승인된 리디렉션 URI**는 **비워 둡니다**
7. **`만들기`** 클릭
8. 창에 **클라이언트 ID**가 나옵니다 (`숫자-글자.apps.googleusercontent.com` 형태) → **복사**

> ⚠️ 같은 창에 **클라이언트 보안 비밀(Client secret)** 도 보입니다.
> **이건 쓰지 않습니다. 어디에도 붙여넣지 마세요.** 우리 방식(브라우저 로그인)은 ID만 씁니다.
> 클라이언트 ID는 공개돼도 되는 값이라 코드에 넣어도 안전합니다.

## 5단계 · config.js에 넣기

Claude Code에 이렇게 말합니다:

```
config.js의 CLIENT_ID에 이 값을 넣어줘.
(여기에 복사한 클라이언트 ID 붙여넣기)
```

끝났습니다. [STEP 06 문서](connect-sheets.md)로 가서 시트 연결을 시작하세요.

## 나중에 · 팀원과 함께 쓰려면

여러분 앱을 회사 팀원이 쓰게 하려면 세 가지를 해 주면 됩니다:

1. **테스트 사용자 추가** — 3단계의 그 자리에 팀원의 Google 이메일 추가
2. **시트 공유** — Google Sheets의 `공유` 버튼으로 팀원을 **편집자**로 초대
   (앱이 팀원 이름으로 시트에 쓰려면 시트 자체의 권한도 필요합니다)
3. **앱 주소 전달** — `https://<내아이디>.github.io/<저장소이름>/`

## 자주 막히는 곳

| 증상 | 해결 |
|---|---|
| "조직에서 프로젝트 생성을 제한했습니다" | 회사 계정으로 로그인돼 있습니다. 오른쪽 위 프로필에서 **개인 계정으로 전환**하세요 |
| 결제 계정을 만들라고 함 | 필요 없습니다. 화면을 닫고 위 단계의 메뉴 경로로 다시 들어가세요 |
| 로그인하면 `403 access_denied` | 3단계의 **테스트 사용자에 내 이메일이 없는** 경우입니다. 추가하고 1~2분 뒤 다시 |
| 로그인하면 `origin_mismatch` | 4단계 원본 주소가 틀렸습니다. `https://<내아이디>.github.io` — 끝에 `/`도, 저장소 이름도 없이. 고친 뒤 **5분쯤 기다렸다가** 다시 |
| "Google에서 확인하지 않은 앱" 경고 | **정상입니다.** 심사받지 않은 내 앱이라 그렇습니다. [STEP 06 문서](connect-sheets.md)의 안내대로 `고급 → 이동`으로 진행하세요 |
