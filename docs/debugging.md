# 안 될 때 — 디버깅

> 뭔가 안 될 때, 언제든 펴 보세요

## 디버깅이란

**기대한 것과 실제가 다를 때, 그 차이의 원인을 좁혀 가는 일**입니다.

여러분의 디버거는 Claude Code입니다.
여러분이 할 일은 코드를 고치는 게 아니라 — **상황을 잘 설명하는 것**입니다.

---

## 상황 설명 4줄 ⭐ (이 워크샵에서 가져갈 가장 쓸모 있는 것)

"안 돼요"라고만 하면 Claude Code도 답답합니다. 대신 이 네 줄을 채우세요.

```
1. 하려던 것 : (예: 화면에서 추가 버튼을 눌러 시트에 데이터를 넣으려고 했어)
2. 한 동작   : (예: 이름에 "홍길동", 수량에 "3"을 넣고 추가 버튼을 눌렀어)
3. 일어난 일 : (예: 화면이 잠깐 멈추더니 아무 일도 안 일어났어.
                   빨간 글씨로 "403 The caller does not have permission"이 떴어)
4. 기대한 것 : (예: 시트 맨 아래에 새 행이 생기고 화면 표에도 나와야 했어)
```

**3번이 가장 중요합니다.** 화면에 뜬 글씨는 **한 글자도 바꾸지 말고 그대로** 옮기세요.
영어라서 무슨 뜻인지 몰라도 괜찮습니다. Claude Code는 압니다.

---

## 한 단계 더 · 개발자 도구 (F12)

화면에는 아무것도 안 뜨는데 동작만 안 될 때가 있습니다.
브라우저가 오류를 **숨겨 놓은** 경우입니다.

1. 문제가 생긴 페이지에서 키보드 **`F12`** 를 누릅니다
2. 위쪽 탭 중 **`Console`(콘솔)** 클릭
3. **빨간색 글씨**가 있으면 그게 오류입니다
4. 빨간 줄을 **마우스로 드래그해서 복사**합니다
5. Claude Code에 붙여넣고 이렇게 말합니다:

```
F12 콘솔에 이런 오류가 떴어. 무슨 뜻인지 알려주고 고쳐줘.

(여기에 붙여넣기)
```

> 💡 콘솔에는 빨간 글씨가 여러 줄 있을 수 있습니다. **맨 위의 것부터** 보세요.
> 아래 것들은 대개 첫 오류 때문에 딸려 나온 결과입니다.

**`Network`(네트워크) 탭**도 유용합니다.
시트 연결이 안 될 때 여기서 빨간 줄을 찾아 클릭하면, Google이 보낸 진짜 이유가 보입니다.

---

## 그래도 안 될 때의 순서

1. **같은 프롬프트를 한 번 더** 실행합니다 (의외로 자주 해결됩니다)
2. **페이지를 새로고침**합니다 (`Ctrl` + `Shift` + `R` — 캐시까지 지웁니다)
3. **배포된 주소인지** 확인합니다 (`file:///`이면 시트 연결은 무조건 안 됩니다)
4. **연결 버튼을 다시** 누릅니다 (로그인은 1시간이면 만료됩니다)
5. [시트 연결 문서의 오류 표](connect-sheets.md#자주-나오는-오류)에서 찾아봅니다
6. **상황 설명 4줄**로 Claude Code에게 말합니다
7. 손을 듭니다

## 되돌리고 싶을 때

크게 망가뜨렸다고 느껴지면 겁내지 마세요. GitHub에 기록이 남아 있습니다.

```
방금 한 작업 때문에 오히려 망가졌어. 마지막으로 저장(커밋)했던 상태로 되돌려줘.
되돌리기 전에 무엇이 사라지는지 먼저 알려줘.
```

**여러분의 데이터는 시트에 있습니다.** 코드를 되돌려도 데이터는 그대로입니다.
이게 시트를 데이터 원본으로 쓰는 이유 중 하나입니다.
